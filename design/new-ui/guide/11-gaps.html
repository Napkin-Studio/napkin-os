Open decisions in the feature records

new-ui-shell (verifying)

  • Agency colours are an admin table in code; should admins set them in the running studio, and who is an admin?
  • Is the call card at the top of the Decisions drawer what the owner meant by "its card"?
  • Looks right only for an unverified finding: keep that line?
  • Set aside is per person, per browser (localStorage). Should it travel across devices?
  • The landing polls the library every 5 s while a document is open. Acceptable, or should the host push run changes?

brief-new-ui (verifying)

  • Save · PDF prints the A4 sheet; keep Grid PDF / Grid HTML in the Save menu, or retire them?
  • Client copy · PDF asks for a lock first; also offer it from the bar's Share?
  • Grid PDF fails closed in the web shell (nested iframe). Scope the grid CSS, or leave grid to desktop?
  • Cover and Why notes (record says not built; live build offers both: confirm they are wanted).
  • Section headings follow reading order after a rearrange; keep or drop?
  • Colour swatches: switch to the client's Brand Clan colours once brand-clan merges?
  • The folder band above the brief moved onto the sheet and into the tab. Confirm that counts as moved, not removed.

research-new-ui (verifying)

  • A click on a figure opens its card in the panel first, and the drawer is one click further. Keep?
  • The example has no sources member, so the projection has no sources.
  • Research this (on a gap) fills Ask and runs nothing until Ask is pressed. Should it run research_lens for one cell?
  • Read the ask again moved under the ask; also keep it in the Report box?
  • Per-section Ask boxes folded into one Ask with an About choice. Is About enough?

spinoff-and-links (verifying)

  • Owner to confirm the changed build order (linking ported from feat/brand-clan).
  • GET /related reads every manifest per request; index it now or later?
  • Which documents link to which (Brief takes research many and Brand Clan one; Deck/Production take one brief).
  • The brief fields a research proposes from (no market or brand on a brief).
  • A spin-off carries the parent's links. Keep, or show them only as carried?
  • The Production Tool will need the same by_source declaration.

doc-app-upgrade (building, on feat/doc-app-upgrade)

  • The compat fixture test is not built yet (no previous app.lock version).
  • The app.lock digest is over template sources; a comment-only edit needs a bump.
  • The update notice sits in the banner row under the bar, not inside the Decisions drawer.
  • The two-sessions 409 test and the roll-forward middleware test are not written.
  • Refreshing installed apps on desktop gets its own feature record.

Open in the design files

  • Brief side tab (sidetab/final.md, risks): Save · PDF and Draft it again leaving the tab; Lock and Needs you out of view in the part view (covered by the crumb's call count and "ready to lock" line); contenteditable for lists and names (paste, IME, tests); whether Done/Cancel in the tab is too far from the field (fallback: a small floating Done at the field); partView options per template; merging Review flags and open questions into Needs you changes what "lockable" counts.
  • Research panel (rsidebar/final.md, risks): Save and Redo in the bar; glyphs need learning (the Key); grouping hides members (Find in map searches inside groups); shared lineKind/confBars code between Brief and Research; Doc B's category mismatch as a new kind of check (owner to confirm).
  • Agency colours: set in code by an admin; a studio settings route is open.
