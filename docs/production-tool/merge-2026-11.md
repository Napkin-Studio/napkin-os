## The written rule

1. `production-tool/**` takes the Production line, and re-applies this build's spend guard
   (`relay/director/spend.py`, called by `providers/runway.py` before a request is built) and its
   attributed writes (every `/patch-data` names an agent and an action, ADR-004).
2. The shell (`app/src/shell/SignIn.tsx`, `Launcher.tsx`, `app/src/host/http.ts`, `app/pwa/sw.js`) takes
   this build and re-adds only the production flag (the session's `production`, the signed-out
   `/?next=/production/...` return, and `/production/*` left to the server by the service worker).
3. `crates/napkin-web/src/api.rs`, `lib.rs`, `main.rs` and `Cargo.toml` are joined so no route of either side is
   lost.
4. Infra, `scripts/check.sh`, `.github/workflows/ci.yml`, `.githooks/pre-push` and `CLAUDE.md` are the union.
5. A binary record keeps this build's file; the other side's changes are re-applied with `clan patch-data`
   and a `clan patch-decision` says so, naming `132c1a8f`.
6. Where both sides changed the same function for different reasons, both behaviours are kept. No conflict
   is resolved by deleting a test.

## Every route the line adds, and the check on each

All of them are mounted only when `NAPKIN_PRODUCTION_RELAY_URL` is set and the server has accounts (anonymous mode never
mounts them). Each runs, in order, behind: the tenant layer (`tenant::layer`: the signed session names the person and
their agency, its roles dropped; none is a 401), `live::live_roles` (the People store's roles and name on every request;
a person no longer on it is signed out with a 401) and `production::gate` (an account with no agency is a 401; a person
whose roles give no Production door, `roles::Table::opens_production` over the agency's door table, is a 403). No cookie,
token, identity provider or document grants it; `directory.rs` and a roles claim are not brought back.

| Route | What it is | Check |
|---|---|---|
| `GET /production`, `/production/`, `/production/*` | the tool's build (`NAPKIN_PRODUCTION_STATIC`), its `index.html` for its own routes | the three layers above; signed out, a page visit is a 401 with a page that sends the browser to `/?next=` |
| `GET /production/assets/*` | hashed assets, a year's cache | the three layers |
| `ANY /production/api/*` | the proxy to the relay (`{relay}/api/*`), with one signed `X-Napkin-Identity` (v1, 60 s, body hash) | the three layers, then a write from another origin is a 403; bodies over 4.5 MB a 413; only five request headers forwarded, four passed back |
| `GET /api/session` (field `production`) | tells the shell the tool is here for this person | inside the shell API's own layers; true only when mounted and `opens_production` holds |

The roles that open it by the default table: producer, art director, copywriter (their homes have a Stills, Video and
motion, or Formats and in situ door), and admin and demo. Planning, creative director, account service, management, the
Agency Brain and traffic do not. Question for the owner: is that the right list?

## The two spend guards

- This build's: `production-tool/relay/director/spend.py` (euro, per environment day cap, run cap, pause switch).
  `providers/runway.py` `submit` calls `spend.check` first, before any request is built (`_guard_estimate` prices the job
  with `contracts/pricing.py`); a refusal is `spend_stop` and nothing is sent. The model wires call `guard_spend`.
  `service.py` sets the run (`spend.set_run`) before the director and the submit.
- The line's: `production-tool/relay/ledger.py` (USD, global total and per-agency month), admitted in `service.py`
  before a job is queued. Untouched.
- Both must pass; a refusal by either sends nothing. `relay/tests/test_spend.py` is unchanged and green.
  `relay/tests/test_spend_line_ops.py` submits frame_edit, upscale, resize and cutdown with `NAPKIN_SPEND_CAP_EUR=0`
  (locally, and deployed with paid calls on): each is `spend_stop` with no request at the mock transport; through the
  whole relay a frame_edit is admitted by the ledger, refused by the guard, and nothing is posted.
