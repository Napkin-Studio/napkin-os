# Runway and its routed models: what they can do for layers today

Sweep date: 2026-10-23. Sources were read at the primary where possible (Runway OpenAPI 3.1 at `https://docs.dev.runwayml.com/openapi.json`, Runway docs as Markdown at `docs.dev.runwayml.com/*.md`, Runway help centre via its public Zendesk JSON API, Runway product changelog, ByteDance Seed blog, BytePlus docs and pricing, OpenAI API reference and changelog, fal, Hugging Face, arXiv, Together). Anything not opened at a primary source is marked **unverified**. Note: the brief at `scratchpad/delayering/brief.md` did not exist when this agent ran; the sweep followed the angle text alone. The session's web-search budget ran out near the end, so two minor checks (Bria's own FIBO Edit docs, Google's statement on alpha beyond its image-generation page) were done by fetch only or not at all, and are marked.

## Short answer

Runway's API has **no layered output, no segmentation and no background removal** today. The whole OpenAPI spec contains zero occurrences of "layer", "cutout", "birefnet" or "segment" (outside video multi-shot prompts). What it does have, for our purpose:

1. **Generative alpha**: `gpt_image_2_5_sunburst` accepts `background: "transparent"` and returns a PNG with an alpha channel; `gpt_image_2` now lists the same enum (OpenAI calls it "preview"); `gpt_image_2_5_flare` is `opaque`/`auto` only. This generates a new image on alpha; it is not a cut-out of existing pixels.
2. **One real mask**: `ideogram_4_5` takes `maskUri` (black = edit, white = keep, same size as the first reference) and `preciseEdit` (whole-image edit that keeps composition and size). We must supply the mask.
3. **Seedream 5.0 on Runway's API is flat**: `seedream5_pro`, `seedream5_lite` and `seedream5_flash` expose prompt, ratio, `outputFormat` png/jpeg, reference images, `outputCount` and (pro/lite) `grounding`. No `layer`, `layered output`, `point-to-edit`, mask or bbox parameter exists.
4. **Runway does expose layers, but only in the web app**: "Seedream 5.0 Pro Layers" (Tool mode, Image tab, 18 credits per run, "PNG layers, transparent support", prompt optional) and "Seedream 5.0 Flash Layers" (4 credits per image), plus BiRefNet v2 background removal (1 credit per image) in Runway MCP, and a prompt-driven "Segment Image" node in Workflows. None of these is on Runway Dev's API.
5. ByteDance's own API (BytePlus ModelArk) offers `layer_decomposition: true` on Seedream 5.0 Pro: one input image, base image plus up to 16 transparent PNG layers with z-index, name, description and bounding boxes, at $0.0225 per layer (≤2.61 MP). This is the capability Runway's web app wraps and its API does not.
6. The gpt_image_2 transparency conflict resolves as: Runway's changelog entry of 2026-04-23 ("transparent backgrounds are not supported") predates OpenAI's 2026-08-20 change that added transparency to gpt-image-2 "in preview"; the OpenAPI is the current contract. Whether Runway's `gpt_image_2` request with `transparent` actually succeeds is **unverified** (no key used in this sweep).

## A. Runway API, `POST /v1/text_to_image`, per model

All from the OpenAPI spec (`https://docs.dev.runwayml.com/openapi.json`, `info.version` 2024-11-06, fetched 2026-10-23; the spec already includes the 2026-10-21 Nano Banana 2 Lite entry, so it is current) unless stated. Credits are $0.01 each (spec `info.description`; pricing at `https://docs.dev.runwayml.com/guides/pricing.md`).

### gpt_image_2
- `background`: enum `transparent | opaque | auto`; description: "Background treatment. Defaults to `auto`, which lets the model pick. Use `transparent` to generate a PNG with an alpha-channel background." (OpenAPI, 2026-10-23)
- `quality` low/medium/high/auto (default high); up to 16 tagged references; `outputCount` 1-10; 30 fixed ratios plus `auto`. No `outputFormat` parameter (PNG is implied by the transparent description).
- Pricing: 1/5/20 credits at 1K-2K, 2/11/41 at 4K and `auto` (pricing.md).
- Runway changelog, 2026-04-23: "Unlike `gpt_image_1`, transparent backgrounds are not supported." (`https://docs.dev.runwayml.com/api-details/api_changelog.md`). See section E for the resolution.

### gpt_image_2_5_flare and gpt_image_2_5_sunburst
- Sunburst `background`: `transparent | opaque | auto`, same alpha-PNG wording as above. Flare `background`: `opaque | auto` only. (OpenAPI, 2026-10-23)
- Runway changelog, 2026-09-08: "Sunburst can return transparent backgrounds with `background: "transparent"`; Flare supports `opaque` and `auto` only. Billed at 1-76 credits per image by quality and resolution, plus 1 credit per reference image per generated image." (api_changelog.md)
- `quality` low/medium/high/xhigh/max (default high); 16 tagged refs; `outputCount` 1-10. Reference images are charged per generated image (pricing.md).

### ideogram_4_5
- `maskUri`: "A black-and-white mask the same size as the first reference image. Black areas are edited and white areas are preserved. Supports up to 3 additional reference images." Accepts HTTPS URL, Runway upload URI or data URI up to 5 MB. (OpenAPI, 2026-10-23)
- `preciseEdit` (boolean): "When true, edit the first reference image while preserving its composition and dimensions. Requires at least one reference image."
- `referenceImages` up to 5: "With `maskUri` or `preciseEdit`, the first image is the one being edited and the rest are references."
- `ratio`: "Not available with `maskUri` or `preciseEdit`, which keep the size of the first reference image."
- `quality` very_low/low/medium/high = 1/4/8/25 credits; defaults to medium with references, high otherwise and with `preciseEdit`; `very_low` needs references and is not allowed with `preciseEdit`. `outputCount` 1-8. (OpenAPI and pricing.md; changelog 2026-10-12.)
- Ideogram's own (legacy v1) edit reference uses the same convention: "Black regions in the mask should match up with the regions of the image that you would like to edit." (`https://developer.ideogram.ai/api-reference/api-reference/edit-v3`, undated, marked legacy.)
- Runway's web pricing page describes Ideogram 4.5 as "Image generation and precise masked editing" (`https://academy.runwayml.com/models-pricing`, undated).

### seedream5_pro, seedream5_lite, seedream5_flash
- Parameters (OpenAPI, 2026-10-23): `promptText` (≤4,000 chars), `ratio` (pro: 14 sizes 1K/2K + `auto_1k`/`auto_2k`; lite: 16 sizes 2K/3K or freeform 3.69-16.8 MP; flash: 16 sizes 1K/2K + auto tiers), `outputFormat` `png | jpeg` (default png), `referenceImages` (pro 10, lite 14, flash 10; "Reference by upload order in prompt text (Figure 1, Figure 2, etc.)"), `outputCount` 1-4, `grounding` boolean (pro and lite only: live web search).
- **No** `layer`, `layerDecomposition`, `layered`, `point`, `bbox`, `mask` or `background` parameter on any Seedream variant. A search of the whole spec for "layer" returns 0 hits.
- Pricing: pro 5 credits (1K) / 9 (2K); lite 4; flash 2 (pricing.md; changelogs 2026-07-08, 2026-07-10, 2026-10-15).
- The models guide (`https://docs.dev.runwayml.com/guides/models.md`) lists the Seedream ids but its per-model descriptions are rendered client-side (`<ModelCatalog />`), so the phrase "layer control" that the catalogue quoted from the models page could not be re-read as text in this sweep.

### nano_banana_2.1, gemini_image3_pro, gemini_image3.1_flash(_lite)
- `nano_banana_2.1`: up to 14 refs with optional tags, `thinkingLevel` minimal/medium/high, `outputCount` 1-4, 42 ratios to 4K. No `outputFormat`, `background` or mask. 4/6/12 credits by tier. (OpenAPI; changelog 2026-10-06.)
- `gemini_image3_pro`: up to 14 refs, each with `subject: "object" | "human"` (up to nine object references "with high-fidelity images of objects to include in the output"); `outputCount` 1 or 4; no `outputFormat`, `background` or mask. 20/40 credits. (OpenAPI; changelog 2026-04-30.)
- Google's own image-generation page (`https://ai.google.dev/gemini-api/docs/image-generation`, read in full, undated) never mentions transparent backgrounds, alpha channels or background removal; examples return `image/jpeg` or `image/png`. So a "cut-out on transparent" from these models is not a documented capability; a flat-colour background is prompt behaviour only. Runway's own help centre documents exactly that workaround for its Gen-4 references: "Use a Reference image of your subject with a prompt specifying to remove and replace the background with a solid color." (`https://help.runwayml.com/hc/en-us/articles/41170686463635-Advanced-References-Use-Cases`, updated 2026-04-20.)

### grok_imagine_image_2
- `edit` (boolean): "When true with exactly one reference image, edit that image directly instead of using it as a loose visual reference. With several reference images the prompt describes how they should be edited or combined. Requires at least one reference image." Up to 3 refs (1 credit each per request), `quality` low/medium, `outputCount` 1-4. No mask or background parameter. (OpenAPI; changelog 2026-08-11.)

### bria_fibo_edit_1_5
- "1 to 4 images to edit. With several, the instruction describes how to combine them." `outputFormat` png/jpeg, `seed`, `ratio` auto or nine 1 MP sizes (choosing a size needs ≥2 images). No mask or background parameter. 5 credits per image. (OpenAPI; changelog 2026-10-08.) Bria's own documentation for FIBO Edit was not reached (search budget), so whether an instruction like "remove the background" yields alpha through Runway is **unverified**.

### muse_image
- `outputFormat` `webp | png | jpeg` (default png), up to 10 refs ("the model edits and combines them as your prompt describes"), `outputCount` 1-10, 1 credit per image. No mask or background parameter. (OpenAPI; changelog 2026-08-26.)

## B. Other Runway API routes

- `POST /v1/image_upscale`, model `magnific_precision_upscaler_v2`: input 300-8000 px per side, `scaleFactor` 2/4/8/16 (default 2), output ≤25.3 MP, `sharpen`, `smartGrain`, `ultraDetail` 0-100, `flavor` sublime/photo/photo_denoiser. 25 credits, 150 above 4096 px. The spec says nothing about alpha preservation on upscale (**unverified** whether a transparent PNG survives). (OpenAPI; pricing.md.)
- `POST /v1/generate/image` (Model Router): model-agnostic input is `promptText`, `referenceImages`, `aspectRatio`, `resolution`, `outputCount`, `seed`, `contentModeration`. No background, mask or layer option; routing cannot reach Sunburst's transparency. (OpenAPI.)
- Recipes: `product_swap` is video-only (reference video 1.8-15 s, `originalProductImage`, 1-10 `newProductImages` with optional `view` front/side/back; output 4-15 s at 720p/1080p). `product_campaign_image` takes one product image plus a brief and returns four campaign images. Neither isolates anything; both docs tell you to supply a product "cleanly isolated from its background" as input. (`https://docs.dev.runwayml.com/recipes/product-swap.md`, `.../recipes/product-campaign-image.md`, versions `2026-06`.)
- `POST /v1/workflows/{id}`: "Start a new task to execute a published workflow. You can optionally provide custom input values via `nodeOutputs` to override the defaults defined in the workflow graph." Overrides include image assets by URI. `GET /v1/workflows/{id}` returns the graph. This is the one API door into web-app-only nodes (see C). (OpenAPI; `https://docs.dev.runwayml.com/api.md`.)
- Outputs: task output is a list of ephemeral URLs that "expire within 24-48 hours"; no per-format notes. (`https://docs.dev.runwayml.com/assets/outputs.md`.)

- **Seedream 5.0 Pro Layers** (product changelog 2026-08-19): "Split images into layers with a new tool that lets you toggle and transform each layer independently. Ideal for fine-grained image editing and asset extraction." (`https://runway.com/changelog`.)
- Help article "Editing images with Seedream 5.0 Layers" (created 2026-08-20, updated 2026-08-24): "It splits a single image into separate, editable layers ... isolate the subject, background, and other elements into individual layers you can toggle, reposition, or transform independently." "prompts are optional ... describe the specific elements you want separated." Only the separation step costs credits; layers export via bulk download from Recents. ## D. What ByteDance means by "layered output" and whether Runway exposes it

- ByteDance Seed blog, 2026-07-08, "Introducing Seedream 5.0 Pro": "supports intelligent layer separation. Through text descriptions, it can separate an image into independent layers, outputting editable design assets." A poster can be split "into more than 10 independent layers" (text, subject, background, decorations); "These layers retain their transparency and can be freely dragged or scaled"; "The background areas previously obscured by the main subject are also seamlessly inpainted and restored." Spatial editing: the model "translates coordinate information provided by users through point selection, lasso selection, box selection, and doodling into deterministic, local editing instructions." No technical report or arXiv link; the phrase "point-to-edit" does not appear. (`https://seed.bytedance.com/en/blog/beyond-generation-it-understands-design-introducing-seedream-5-0-pro`.)
- No Seedream 5.0 technical report was found on arXiv; the latest is Seedream 4.0 (arXiv 2509.20427). Seed's blog lists only Seedream 5.0 Lite (2026-02-13) and Pro (2026-07-08). (`https://seed.bytedance.com/en/blog_list/visual`.)
- BytePlus overview "Seedream 5.0 overview" (updated 2026-09-23): "Layer decomposition takes one input image and separates it into a base image plus up to 16 independently editable layers"; layers are PNGs with alpha; enabled with `layer_decomposition: true`; capability table: Layer decomposition **Yes for 5.0 pro, No for 5.0 lite**; interactive editing "Yes for pro, No for lite" using `<point>x y</point>` or `<bbox>x1 y1 x2 y2</bbox>` tags in the prompt on a normalised 0-999 grid; "this controls only the base image; layers are always returned as PNG"; size for decomposition `auto`/`1K`/`1.5K`/`2K`. Model ids `dola-seedream-5-0-pro-260628`, `seedream-5-0-lite-260128`. (`https://ai.byteplus.com/resources/seedream-5-0-overview-what-we-know-about-this-version`.)
- BytePlus ModelArk pricing (undated): `dola-seedream-5-0-pro-260628` output $0.045 per image ≤2.61 MP, $0.09 above; **layer decomposition $0.0225 per layer ≤2.61 MP, $0.045 above**, "each layer ... billed separately"; `dola-seedream-5-0-flash-260915` $0.018 per image, no layer rate listed; `seedream-5-0-lite-260128` $0.035. (`https://ai.byteplus.com/ark/region:ap-southeast-1/docs/model-pricing`.)
- BytePlus "Image generation API" doc (`https://docs.byteplus.com/en/docs/ModelArk/1541523`, last updated 2026-10-17) is rendered client-side and could not be read as text. Via search-engine excerpts of that page (**unverified at primary**): decomposition needs exactly one image (several cause an error); prompt optional ("the model automatically identifies all major elements"); response gives each layer a stacking index (base fixed at 0, layers from 1), name, description and bounding box in absolute and normalised forms; "If any layer fails to generate, the entire request fails"; capability listed for "pro and flash".
- Third-party hosts corroborate the shape: Runware (2026-07-08) `settings.layerDecomposition` boolean, `outputs.layers` max 16 with `description`, `boundingBox.absolute/normalized`, `name`, `url`, `uuid`, `zIndex`, "Each layer is a PNG with transparency", "a single request can cost up to 17 times the per-image price", `background` and `positivePrompt` cannot be combined with decomposition (`https://runware.ai/docs/models/bytedance-seedream-5-0-pro`). ComfyUI docs: "describe elements in natural language to control the separation" or "target exact regions with bounding-box tags" (`https://docs.comfy.org/tutorials/partner-nodes/bytedance/seedream-5-pro`).
- **Runway exposure**: web app only (section C). Runway Dev's `seedream5_pro` and `seedream5_flash` carry none of this (section A). Because Runway's `promptText` is a free string, it is **untested** whether `<point>`/`<bbox>` tags pass through to ByteDance's interactive editing.

## E. OpenAI gpt-image-2 / 2.5 transparency: resolving the catalogue conflict

- OpenAI API reference, Create image (`https://developers.openai.com/api/reference/python/resources/images/methods/generate`, read 2026-10-23): `background` "Must be one of `transparent`, `opaque`, or `auto` (default value)"; "`gpt-image-2.5-sunburst` and `gpt-image-2.5-flare`, including their `2026-09-08` snapshots, support `opaque` and `transparent` backgrounds"; "For `gpt-image-2` and `gpt-image-2-2026-04-21`, this support is in preview"; "When using `transparent`, set the output format to `png` or `webp`." `output_format` is png/jpeg/webp.
- OpenAI changelog (`https://developers.openai.com/api/docs/changelog`): 2026-04-21 GPT Image 2 released; **2026-08-20** "Transparent backgrounds are now available in preview for `gpt-image-2` and `gpt-image-2-2026-04-21` in the Images API"; 2026-09-08 GPT Image 2.5 Sunburst and Flare released.
- OpenAI model page for gpt-image-2 (`https://developers.openai.com/api/docs/models/gpt-image-2`) lists only "inpainting" under supported features and names the default snapshot `gpt-image-2-2026-04-21`; no deprecation note.
- Note on OpenAI's own docs: the reference says Flare supports transparent, while Runway's Flare exposes `opaque | auto` only. Runway has chosen not to pass Flare transparency through (OpenAPI, 2026-10-23).
- Third-party claim that "OpenAI shut down transparent backgrounds for gpt-image-2 on 2026-09-30" (`https://docs.apiyi.com/en/live/2026-08/gpt-image-2-transparent-background`, article dated 2026-08-21 with a later warning box) is **unverified** and contradicted by OpenAI's reference still stating "in preview" on 2026-10-23.
- Conclusion: Runway's 2026-04-23 changelog line was true when written and is stale; the OpenAPI enum is the live contract. A one-credit `quality: "low"` test of `gpt_image_2` with `background: "transparent"` would settle whether Runway's proxy accepts it.

## What this means for Napkin

- On Runway's API, "delayering" an existing image is not available as a primitive. The nearest tools are generative: `gpt_image_2_5_sunburst` with `background: "transparent"` (16 credits plus 1 per reference per output at high quality) re-synthesises an element on alpha from references rather than lifting the original pixels, so fidelity to the client's artwork is a model-behaviour question, not a contract.
- The only pixel-targeted operation is `ideogram_4_5` `maskUri` (black = edit, 8 credits at medium, 25 at high, output at the first reference's size). It needs a mask we produce ourselves (user-drawn or client-side segmentation), and it edits, it does not extract. A plausible Runway-only layer pipeline is: our own mask → Ideogram inpaints the background behind the removed element → we composite the masked-out pixels as a layer. Two Runway calls per layer at most, one if we only need the clean plate.
- Seedream 5.0 layer decomposition is the one model-side "layered output" that exists, and Runway already runs it (web app, 18 credits per run; Flash Layers 4 credits) and already routes `seedream5_pro`/`seedream5_flash` to ByteDance. The gap is purely API exposure. This is a concrete ask for Runway: expose `layerDecomposition` on `seedream5_pro`/`seedream5_flash` and BiRefNet v2 on Runway Dev.
- Runway Workflows plus `POST /v1/workflows/{id}` may be a legitimate back door today: build a published workflow with the "Segment Image" node (text-prompted extraction, mask refinement) and run it from the API with our image as a `nodeOutputs` override. Untested; the node's output transparency is undocumented, and it is unknown whether the Seedream Layers or BiRefNet nodes exist in Workflows.
- Price picture for the owner: ByteDance direct, Pro decomposition is $0.045 base plus $0.0225 per layer (about $0.41 for 16 layers at 1.5K); Runway web app is a flat $0.18 per run (18 credits); fal's Qwen-Image-Layered is a flat $0.05 for 1-10 RGBA layers. On Runway's API, the comparable spend buys a single Sunburst transparent generation ($0.16+) or one Ideogram masked edit ($0.08-$0.25).
- Nano Banana, Gemini 3 Pro Image, Grok Imagine Image 2, FIBO Edit and Muse have no transparency or mask parameter on Runway; a "cut-out on a flat background" from them is prompt behaviour, which Runway's own help centre recommends for its Gen-4 references but does not guarantee.
- The catalogue's two notes should be amended: `gpt_image_2` transparency is "listed in the OpenAPI, added by OpenAI in preview on 2026-08-20, Runway proxy untested"; `seedream5_flash` is now documented (2026-10-15, 2 credits, 10 references, no layer parameter).
