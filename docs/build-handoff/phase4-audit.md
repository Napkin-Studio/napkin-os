### 2.2 How it works today

The app never calls the engine. It reads `shared/data.yaml` and writes attributed patches. The engine is a command line (`python3 -m deck.run_deck ...` from `engine/`) that runs the whole pipeline in one go, resumable only by the `--stages` directory (a stage runs only when its file is missing). Free path: recorded stage outputs. Paid path: `--live`, "about $0.65-1.25 a deck in the 2026-10-05 eval" (README), "ask first".

Engine stages (`PLAN.md` s4; `engine/deck/run_deck.py:37` `STAGE_FILES` = a0, a, b, c, d): a0 intake (only when there is a gap and something to read), a requirements, b storyline (Gate 1), c three territories plus blind judge (Gate 2), d idea and executions, e copy, fit judge, red team, f validators (code, 27 checks), g render, h visual QA (**not built**, DK-028), insight judge. Swap test: stage b writes `swap_test` on each of three insight candidates (`prompts/b_storyline.md` line 9); a blind insight judge (`prompts/insight_judge.md`, "Swap the client for [client] and the category for [category]: if it still reads...", `stages.insight_judge`) never sees the writer's choice or the swap-test text (`tests/test_thinking.py:213-219`). Types are profiles in data (ADR 0029, proposed).

Gates in the contract: the app's registry has `storyline` (gate 1), `territories` (gate 2), `idea` (gate 3). The server record proposed three gates "storyline (after stage b), territory pick (after c), and the final deck review" and `deck-maker-circle-ui` open question says "reconcile gates (the server design lists storyline, territories, review; this UI needs storyline, territories, idea)". Unreconciled.
